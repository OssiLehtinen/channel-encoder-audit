FDM-Inspired Transformer Input Encoding — Summary
Problem

How to multiplex multiple input signals onto a single token embedding in a transformer, going beyond naive summation of embeddings.
Approach Selected: FDM Analog

Assign each input channel a dedicated, non-overlapping block of embedding dimensions, modulated by a unique carrier frequency. Inspired by Frequency-Division Multiplexing from signal processing.
Key Design Decisions

    Concatenation of per-channel embeddings, not summation — preserves orthogonality by construction
    Log-spaced carrier frequencies per channel to minimize cross-talk
    Signal value as amplitude modulation on a sinusoidal positional carrier (RoPE-style within each block)
    Per-channel dimension block of size d_model / C

Encoding Formula

Each channel kk with value vkvk​ at position tt is encoded as vk⋅sinusoidal(ωk,t)vk​⋅sinusoidal(ωk​,t), concatenated across all CC channels into a single (B, T, d_model) tensor.
Prior Art

    PerceiverIO — closest precedent, uses explicit Fourier features per modality
    RoPE — same frequency-in-dimension-space intuition, but for position not channel identity
    TimesNet — explicit FFT-domain input processing
    The specific combination of FDM-style channel separation + RoPE-style encoding does not appear to have a canonical implementation

Code Produced

A working PyTorch module FDMChannelEncoding implementing the full encoding, plus a recover_channel helper for slicing individual channels out of the embedding at any layer.
Open Implementation Questions

    Missing channels — zero amplitude when absent (clean, no special token needed)
    Variable channel count — reserve full capacity, use subset
    Fixed vs learnable carrier frequencies ωkωk​
    LayerNorm interaction — standard LayerNorm mixes channels; per-channel LayerNorm would preserve separation
    Attention head specialization — may emerge naturally, or could be encouraged with channel-masked heads in early layers
